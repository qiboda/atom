1. 节点化技能
2. 节点支持rust，脚本以及图形化
3. buff作为节点的一部分，不作为独立的实体存在
4. 技能的打断方式，所有effect Node，独立设置是否打断。
5. 状态管理使用buff节点的状态类型来确定，buff的子节点则作为buff的具体效果。
6. buff的状态以及游戏内部的状态使用gameplay tag，并且支持多个tag并存，类似tag。
7. 属性管理支持属性的分类，以及范围控制，以及相互关系（多个计算得到一个父级属性）。属性的分层控制。属性内部和属性间公式定义。属性的更新（实时更新还是触发更新）以及缓存（是否有）。
8. 部分数值使用曲线控制
9. 如何支持回滚（编辑器不支持回滚）。
10. 如何支持序列化以及存档，节点添加guid，并通过guid引用，如此来存储。
11. 网络的同步方案，如何支持预测以及回滚。
12. debug支持。
13. 事件驱动。但支持时间线，多时间线逻辑。
14. 支持检测技能的结束。技能节点有范围后，一切都没有了问题。
15. 地形效果，陷阱等减速，眩晕效果，是否应该使用技能系统呢？技能以及效果节点的划分。如何在不支持技能，属性状态等情况下，使用Effect Node。
16. 技能的客户端表现。
17. 技能节点池化。节点分为瞬发和范围时常，以及循环播放，有时长的事件触发等。
18. 编辑器使用多时间轨道，并且显示技能节点。技能节点，决定了是否显示一个轨道（有时间节点，或者有时长的事件节点），并且可以根据轨道决定播放的时机，以及设定参数。事件触发怎么显示在轨道上？显示在轨道的子轨道中了。
19. 如何处理实体A播放技能A，里面使实体B播放技能B。两个独立处理。但通过传递额外的上下文来影响B。
20. 效果方案的嵌套和继承等实现。
21. 节点output pin需要分组，每个Exec对应一组数据输出。每个Exec设置是否是异步的。
22. 每个节点的input pin 都是启动的输入（同输出有一个Exec），输入需要区分是否是可选的输入，以及默认值问题。
23. input pin 必须是引用，或者自己设置的值，或者一个函数，或者一个简单的表达式。
24. 节点的分类，分为瞬时节点（包括，数值操作，加减法，赋值，取值等，或者，简单的一个同步函数调用），和状态节点（异步状态调用）。
25. 异步节点的输出不能连接到后续的异步节点的输入上。如果需要，需要存入临时变量中，再获取。这个可以给所有节点一个layer的变量，不同layer的不可以连接（通过输出pin的exec决定）。
26. 支持记录节点运行时，展开所有的异步节点，并绘制成图。Debug用。
27. 技能节点可以根据是否是事件触发分组，然后按时间线分组，每个分组都可以在范围内拖动，这个可以查看在怎样的时间点触发效果最好。

  

编辑器：

1. 编辑器负责界面，以及编译后导出一个配置文件（或者脚本文件），之后，技能系统根据文件内容，组成逻辑，并运行。
2. 运行期间，通过socket发送debug信息到编辑器界面。
3. 所以，目前完成第一步，实现技能系统，手动拼接出技能。
4. 之后定义脚本或者配置文件的格式。
5. 最后实现编辑器。
